Developer Setup

How to get the Implementation MS Backend running locally. This guide covers forking the repo, running Docker containers, seeding databases from staging, configuring RabbitMQ, and running the data enrichment process.

Prerequisites

  • Docker Desktop installed and running
  • Git with access to the RTVInc GitHub organisation
  • Credentials doc (shared separately — contains staging DB login details)

Familiarity with Laravel, Domain-Driven Design, Event-Driven Design, and Microservices is expected. The backend also contains some ExpressJS services.

Getting Started

1. Fork and clone

# Fork from RTVInc/implementation-ms-backend in GitHub, then:
git clone git@github.com:YOUR_FORK/implementation-ms-backend.git
cd implementation-ms-backend

2. Configure environment files

Each microservice requires its own .env file with DB credentials, queue names, and service-specific config. There is also a root-level .env for Docker Compose.

# Copy the example Docker Compose config
cp docker-compose.example.yml docker-compose.yml

# Create .env files for each service (DB, queue config)
# Values are in the credentials doc

3. Build and run

# Build and start all containers
make rebuild

# Install PHP packages in each service container
make install-packages

# Run database migrations
make db-migrate

# Start the application
make run

Once running, open Docker Desktop to verify all containers are healthy.

Database Setup

Always import complete dumps from staging. Partial dumps cause enrichment failures downstream.

The local databases need to be seeded from staging to have real data. This is done by exporting dumps from the staging databases and importing them locally.

Steps

  1. Open the staging database admin links below and sign in with credentials from the credentials doc
  2. Export the full database as a SQL dump
  3. In Docker Desktop, find the local container for the same service (names match staging names)
  4. Drop all existing tables in the local database
  5. Import the .sql dump — repeat for all services

RabbitMQ Setup

Each microservice has a corresponding RabbitMQ queue and exchange. These must be configured manually after the containers are running.

  1. Open RabbitMQ management UI from Docker Desktop
  2. Navigate to Queues and Streams — add a queue for each service using the names in the table below
  3. Navigate to Exchanges — create a topic exchange for each service
  4. Bind each exchange to data_mongo, using the queue name as the routing key

Queues like data_mongo are auto-created. Only the service queues need manual setup.

Data Enrichment

The DataMongo service aggregates data from all other services into a read-optimised MongoDB store. Enrichment must be run after the databases are seeded to populate the analytics layer.

  1. Open the DataMongo API docs at localhost:8045
  2. Open the Users API docs at localhost:8014 and retrieve the API key
  3. In the DataMongo Swagger UI, run each endpoint that contains /enrich — one per service tag
  4. Watch the Docker Desktop logs — confirm no errors in the queues and that profileQueue and datamongoQueue are draining cleanly
  5. Enrichment is complete when data appears in the DataMongo database at localhost:8097/db/data_db

Once enrichment is complete, the full API surface is available for local development and testing.
