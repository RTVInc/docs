System Architecture

Production architecture of the Implementation MS Backend, following a high-availability pattern with distinct layers: User Access, Application & Data, and Operational Tools.

Each microservice runs inside the Kubernetes cluster with 3 replicas. The Tyk API Gateway routes requests by path prefix to the appropriate service. Each service owns its dedicated database.

Service path prefixes

Path PrefixServiceDescription
/user-svc/userwebUser accounts and authentication
/profile-svc/profilewebHousehold and beneficiary profiles
/training-svc/trainingwebTraining session data
/agric-svc/agricwebAgriculture distributions and yields
/vsla-svc/vslawebVSLA groups, savings, and loans
/data-svc/datamongowebAnalytics read store (DataMongo)
/livestock-svc/livestockwebLivestock distribution and follow-up
/leadership-svc/leadershipwebVillage champion registry
/checkin-svc/checkinwebHousehold coaching and check-ins
/workplan-svc/workplanwebProgramme workplans
/dump-svc/dump (worker)Background data enrichment
/notification-svc/notificationwebPush notifications

Example request: https://92mfti4b-gateway.nonproftinnovations.io/data-svc/api/data/trainings/web/web-dashboard?tgd=...
Tyk matches /data-svc/, strips the prefix, and forwards to http://datamongoweb/api/data/...

Load Balancing

flowchart LR
    Client[Web / Mobile] -->|HTTPS| LB[Load Balancer — HAProxy or Nginx Round-robin]
    LB --> Tyk1[Tyk NodePort 30010 — Node 1]
    LB --> Tyk2[Tyk NodePort 30010 — Node 2]
    LB --> Tyk3[Tyk NodePort 30010 — Node 3]
    Tyk1 -->|routes by path| Services[Microservices]
    Tyk2 -->|routes by path| Services
    Tyk3 -->|routes by path| Services

The Gateway/Bastion server runs HAProxy or Nginx to distribute traffic across 3 Kubernetes nodes in round-robin. Each node exposes Tyk Gateway on NodePort 30010.

Load BalancerListen PortAlgorithm
HAProxy8100Round-robin
Nginx80Round-robin (default)

Message Bus (RabbitMQ)

Programme services publish domain events to RabbitMQ exchanges. The DataMongo service subscribes to all topic exchanges, consuming events to build the analytics read store (MongoDB).
