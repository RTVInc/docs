IDS Agriculture Predictions API

Integration guide for external platforms calling the IDS v2 agriculture-value prediction API. Predicts Year 1 and Year 2 agriculture values from household and farm inputs.

Replace {BASE_URL} with the Workmate environment you are targeting (staging or production host). Paths below are absolute from the API origin.

1. Quick start

  1. Obtain credentials from the Workmate team: an API key with scope ids_v2 (preferred for platform backends), or a user account with prediction permissions (JWT).
  2. POST feature inputs to {BASE_URL}/ids-v2/predict/.
  3. Read prediction_year_one, prediction_year_two, and request_id from the response.
  4. Optionally list past results via GET /ids-v2/predictions/ or audit via GET /ids-v2/logs/.

Minimal predict call — API key

curl -sS -X POST "{BASE_URL}/ids-v2/predict/" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: wm_YOUR_KEY_HERE" \
  -d '{
    "region": "east",
    "implementation_type": "Standard",
    "Land_size_agriculture": 1.5,
    "Beans_total_yield": 120,
    "Maize_total_yield": 200
  }'

General model (no region)

curl -sS -X POST "{BASE_URL}/ids-v2/predict/" \
  -H "Content-Type: application/json" \
  -H "X-API-Key: wm_YOUR_KEY_HERE" \
  -d '{
    "implementation_type": "Standard",
    "Land_size_agriculture": 2.5
  }'

Numeric fields omitted from the body default to 0. implementation_type is required. region is optional: include it to use the regional model; omit it (or send null / "") to use the general model.

2. Authentication

Both schemes are accepted on every IDS endpoint. Send one per request.

2.1 API key — recommended for integrations

Keys are issued by Workmate admins (Accounts → API keys). The plain key is shown once at creation (wm_…).

HeaderExample
X-API-Keywm_abcdef0123456789…
Authorization (alternative)ApiKey wm_abcdef0123456789…

The key must include scope ids_v2 or all. Without it the API returns 403.

2.2 JWT — interactive / Workmate UI

  1. Login: POST /accounts/login/ with {"email": "…", "password": "…"}
  2. Use the returned access token: Authorization: Bearer <access_token>

JWT users need Django permissions (see Permissions). Superusers bypass permission checks.

2.3 Auth failures

StatusTypical cause
401Missing, invalid, or expired API key or JWT; revoked key; disabled user
403Authenticated but lacking permission or ids_v2 scope

3. Endpoints

POST/ids-v2/predict/
Runs the active IDS Year 1/2 model, stores the input + outputs, and returns the two predicted values.
FieldDetail
AuthAPI key (ids_v2) or JWT with can_generate_predictions
BodyJSON object — see Request fields
Success200 {"prediction_year_one": 1234.56, "prediction_year_two": 2345.67, "request_id": 42}
GET/ids-v2/predictions/
Returns all stored prediction records (inputs + outputs). Auth: API key (ids_v2) or JWT with can_view_predictions. No pagination currently — plan for potentially large payloads in long-lived environments.
GET/ids-v2/logs/
Audit trail of predict attempts (success and failure), ordered newest first. Same auth as /predictions/. No pagination.

4.1 Categoricals

When region is a non-empty valid value the regional model is used (IDS_year_1_2*). Omit, send null, or send "" for the general model (IDS_Gen_year_1_2*). Unknown non-empty region values return 400.

6. Worked examples

TypeScript / fetch

const BASE_URL = "https://your-workmate-host.example";
const API_KEY = process.env.WORKMATE_IDS_API_KEY!;

type PredictResponse = {
  prediction_year_one: number;
  prediction_year_two: number;
  request_id: number;
};

async function predictAgricultureValue(
  body: Record<string, string | number>,
): Promise<PredictResponse> {
  const res = await fetch(`${BASE_URL}/ids-v2/predict/`, {
    method: "POST",
    headers: {
      "Content-Type": "application/json",
      "X-API-Key": API_KEY,
    },
    body: JSON.stringify(body),
  });
  const data = await res.json();
  if (!res.ok) throw new Error(data?.error ?? `IDS predict failed (${res.status})`);
  return data as PredictResponse;
}

const result = await predictAgricultureValue({
  region: "east",
  implementation_type: "Standard",
  Land_size_agriculture: 1.5,
  Maize_total_yield: 180,
});
console.log(result.prediction_year_one, result.prediction_year_two, result.request_id);

Python / requests

import os, requests

BASE_URL = os.environ["WORKMATE_BASE_URL"].rstrip("/")
API_KEY  = os.environ["WORKMATE_IDS_API_KEY"]

payload = {
    "region": "mid_west",
    "implementation_type": "Replication",
    "Land_size_agriculture": 2.0,
    "Beans_total_yield": 100,
    "Maize_total_yield": 250,
}

r = requests.post(
    f"{BASE_URL}/ids-v2/predict/",
    json=payload,
    headers={"X-API-Key": API_KEY},
    timeout=60,
)
r.raise_for_status()
print(r.json())

curl -sS "{BASE_URL}/ids-v2/logs/" -H "X-API-Key: wm_YOUR_KEY_HERE"

8. Operational notes

How the model works

Inputs are scaled and passed through a BaggingRegressor-style artifact pair (model + scaler/encoders). Two artifact pairs are supported:

  • Regional — active IdsModel upload, or filesystem ids_v2/model_files/IDS_year_1_2.pkl + scaler
  • General — IDS_Gen_year_1_2.pkl + IDS_Gen_year_1_2_scaler.pkl in the same folder. If this pair is missing, requests without region return 500.

Idempotency

POST /predict/ always creates a new prediction row. Retrying the same body produces another request_id. Apply client-side idempotency keys if you need de-duplication.

Timeouts

Allow 30–60 s on the client. Cold starts may load model artifacts into memory on first request after a worker restart or model swap.

Environments

Confirm {BASE_URL} and credentials separately for staging vs production. Model versions can differ per environment when admins activate different uploads.
